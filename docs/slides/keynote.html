The scenario

Lea is a networking student. The exam is in two days.

She has 24 pages of private course notes (a PDF) and 9 questions to prepare.

She wants one file: an answer to each question, the page it comes from, and a quote she can check.

Why not just a chatbot?

  • It has not read your PDF, so it may confidently invent an answer.
  • Your notes are private: they should not leave your machine.
  • A small local model cannot read a whole PDF: its context window is about 3,000 words, the notes are 5,500.

So: search first, give the model only the few passages that matter, and check what it says.

Local Ollama models: qwen3:4b (answers and judge) and nomic-embed-text (embeddings). No LLM framework: plain requests.

R1 · Retrieval 2 stars

  • Chunks of 800 characters, overlap 150, each keeps its page number.
  • Embeddings: a text becomes 768 numbers that stand for its meaning.
  • Cosine similarity picks the 4 closest chunks to the question.
"How do plants make food?"  finds  "Photosynthesis turns light into sugar..."
no shared word, found by meaning. In our tests the right page was always in the top 4.

Ruled out: SQLite or a vector database (a JSON file is enough for hundreds of chunks), LangChain (forbidden, and opaque).

T5 · Structured output 1 star

Our code must use the answer, so the model must answer in a fixed shape:

{ "answer": "The maximum payload ... is 1500 bytes.",
  "page":   8,
  "quote":  "The maximum payload of an Ethernet frame is 1500 bytes" }
  • Ollama's format schema constrains the output; our code validates it.
  • Invalid? Retry twice, then the question is reported as failed. Never written to the file.
  • Finding: with a schema, thinking must be off, or the model returned empty answers or hung.

M4 · A living document 2 stars

The file is the deliverable, not a chat transcript. Re-run one question and only its section changes.

$ sed ... questions.txt > /tmp/q.txt        # reword question 2
$ python -m src.cli data/demo.pdf /tmp/q.txt --only 2
$ diff before.md answers.md               # only section 2 differs
  • Sections are found by invisible markers, in numeric order, written atomically.
  • Tested byte for byte: the other sections never change.

EV1 · Can we trust the answer? 3 stars

Quote check

Plain code: is the quote really in the passages? Exact and cheap. Cannot tell a misread quote.

LLM judge

Reads question, passages and answer: faithful, partial or unfaithful, with a reason. Smarter, but a small, lenient model.

The flag

When the two disagree, the section is marked Review needed. That is how a wrong refusal is caught.

Honest assessment

Works well

  • Whole chain runs locally and automatically
  • Right page ranked first every time
  • File never corrupted, tested byte for byte
  • Two independent checks per answer
  • 392 tests, none needs Ollama

Limits

  • The 4B model sometimes refuses a question the PDF covers (2 of 8)
  • The judge shares the model's weaknesses
  • About 40 s per question on CPU
  • Text PDFs only; one small sample

Next time

  • Fix a model test set before building
  • A separate status for refusals
  • Retry with more chunks when it refuses (reranking)
  • A bigger model if a GPU is available
